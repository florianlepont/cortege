# Phase 23 component inventory and homogenisation plan

Scope: ROADMAP.md Phase 23 criteria 7 (inventory and homogenisation of the design components) and 8 (native libraries and platform components first, a stated reason for each custom component that replaces a native one).

Snapshot: branch `chore/phase-23-components`, level with `origin/main` at `f39dbc51` (2026-10-08). Read-only analysis: no code was changed. Everything below is measured with `grep` and small scripts over `mobile/src` and `mobile/App.tsx`, tests excluded unless said otherwise. Importer counts are the number of distinct non-test files that import the module; a count of 1 usually means "single-screen part", not "generic building block". Where a basename is shared by two files (the two `FactorsList.tsx`), importers were counted by path.

## 9. Batch 8: native control evaluation and the "Why custom" register

### 9.1 Slider and segmented picker (`@expo/ui` 57.0.22, iOS only)

`@expo/ui/swift-ui` `Slider` takes `value`, `min`, `max`, `step`, `onValueChange`, `onEditingChanged` and `Picker` takes `selection`, `onSelectionChange` with `tag` children; both render inside a `Host`. `@expo/ui` is imported only from `*.ios.tsx` files and excluded from Android autolinking (`expo.autolinking.android.exclude`, guarded by `GlassButton.platforms.test.tsx`), and jest maps `@expo/ui/swift-ui` to a small mock (`mobile/test/expo-ui-swift-ui.mock.ts`) that has neither control.

| Need                             | `FactorSliderInput` (G, 5 % steps)                                                                                                                                   | `FactorSegmentedInput` (H, 0/2/5)                                                                                                          |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Min, max, step, controlled value | Supported by `Slider` (`min 0`, `max 100`, `step 5`); the value is a number, the form keeps text                                                                     | Supported by `selection` with string tags                                                                                                  |
| Accessibility                    | Label comes from `label`; the app's `fieldLabel` with the percent and the two step buttons would need re-wiring                                                      | Segments get system labels from the `Text` children; the per-option `accessibilityLabel`, radio role and `testID` of today are not exposed |
| Haptics                          | System tick on steps, not configurable and not testable here                                                                                                         | System, none to configure                                                                                                                  |
| Gloves and sunlight              | The +/- buttons (the field fallback) are not part of `Slider` and stay as custom views next to it                                                                    | Same pill size as today unverifiable without a device                                                                                      |
| Brand look                       | Native track and thumb only; no moss track, no 28 pt thumb                                                                                                           | System segmented look; the brand pills are lost                                                                                            |
| Tests                            | Needs a new `Slider` and `Picker` mock plus `.ios.tsx` and Android twins and a platform test; none of the native behaviour (drag, haptic, VoiceOver) can run in jest | Same                                                                                                                                       |
| Cost of the split                | Two implementations of each control and two test sets, for 2 call sites each                                                                                         | Same                                                                                                                                       |

Recommendation: keep both custom for now and defer to a device spike (Phase 26 or the Android and iOS pass of Phase 28). Reasons: no device is available to check drag feel, VoiceOver adjust gestures, haptics and the glove-sized targets, the field use case values the +/- buttons and the 5 % snap the native slider does not give alone, and the gain (system look) is small against a platform split. Nothing was implemented.
