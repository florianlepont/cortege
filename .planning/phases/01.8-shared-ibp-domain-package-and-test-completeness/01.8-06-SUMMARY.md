# Phase 01.8 Plan 06: API delegates every IBP rule to the package Summary

`IbpRulesService` is now a 28-line adapter over `evaluateIbp` from `@cortege/ibp-domain`, with no rule, allowed set or factor-key list left under `api/src`. The API wire types are aliases of the package contract. The 64 shared parity cases pass through the adapter with the same results as in the package, including `factor_f_group_capped` for MAT-F-02.

## What changed

- **`ibp-rules.service.ts`** (510 → 28 lines). It keeps the `@Injectable() IbpRulesService` DI token, so `surveys.module.ts` and `surveys-sync.service.ts` are unchanged. `validateDraft(input)` and `validateSubmit(input)` call `evaluateIbp(input, "draft" | "submit")`. It re-exports `IbpValidationResult = IbpEvaluation`, `IbpEvaluationInput` and `IbpValidationIssue`.
- **Call sites in `surveys.service.ts`.** `prepareUpsert` and PATCH now pass `{ factors, region_version, vegetation_stage }`. Submit already passed an object and is unchanged. No method fields are passed yet; 01.8-09 adds them.
- **`surveys.types.ts`.**
  - `SurveyUpsertBody` and `SurveyPatchBody` alias `SurveyUpsertPayload` and `SurveyPatchPayload`.
  - `FactorCanonical`, `SyncResultError`, `SyncOperationResult`, `SyncChangeEvent`, `SyncChangeSurvey` and `SyncChangeAttachment` are re-exported from the package.
  - `SurveyRow.status`/`visibility` and `SurveyVisibilityPatchBody.visibility` use the package's `SurveyStatus`/`SurveyVisibility`.
  - Row and DB-only types stay in the API: `SurveyRow`, `SurveyEventRow`, `AttachmentRow`, `ParcelRow`, `SyncChangeEventRow` and `CreateAttachmentBody`.
- **`surveys-sync.service.ts`.** `getSyncChanges` returns `Required<SyncChangesResponse>` instead of an inline copy of the same shape.

### Contract mismatches (the package was not edited)

| Type | API before | Package | Effect |
|---|---|---|---|
| `SurveyUpsertBody` / `SurveyPatchBody` | `region_version?: "ACA" \| "M"` | `region_version?: string` | Looser. Nothing relied on the literal type, and the DTO still validates the value. The bodies also gain the optional `ibp_method_version`, `ibp_cas` and `ibp_cas3_scale` fields, which the DTOs strip until 01.8-09 |
| `SyncChangeSurvey` / `SyncChangeAttachment` | `Pick<SurveyRow/AttachmentRow, …>`, all fields required | most fields optional | Looser. The rows the service returns still satisfy it, so no local narrowing was needed |
| `SyncChangeEvent` | `= SurveyEventRow` | the same fields | Identical |
