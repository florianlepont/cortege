# Phase 01.8 Plan 08: Method version in mobile local storage Summary

The phone now stores `ibp_method_version`, `ibp_cas` and `ibp_cas3_scale` in the schemaless `payload_json` and queued upsert payloads. There is no SQLite migration and `SCHEMA_VERSION` stays 2. Legacy drafts are never stamped. A pulled v3.2 survey keeps its method fields, and completion counts version + cas in place of region + stage for v3.2. The storage wire types and `FACTOR_KEYS` now come from `@cortege/ibp-domain`.

## What was done

**Task 1: types and factor keys from the package** (`35f95d7`)
- `SurveyQueuePayload`, `DraftInput` and `UpdateDraftInput` gain `IbpMethodFields`. `region_version`/`vegetation_stage` are now optional in both draft inputs.
- `SyncBatchOperation`, `SyncBatchError`, `SyncBatchResult`, `SyncBatchResponse`, `RemoteSurvey`, `RemoteAttachment` and `SyncChangesResponse` are now aliases or narrowings of the package types. Every exported name is kept.
- `db.ts`: `FACTOR_KEYS: FactorKey[] = [...SHARED_FACTOR_KEYS]`. `SCHEMA_VERSION = 2` and `LEGACY_DEFAULT_FACTOR_VALUES` are unchanged.

**Task 2: write rule, pull mapping and completion** (RED `70c27de`, GREEN `6c1d605`)
- `applyMethodFields(base, input)` in `utils.ts` sets the write rule, and `createLocalDraft` and `updateLocalDraft` both use it:
  - No version key: the base payload's method fields are kept (no stamping).
  - A given version is written as given. `null` stays `null`.
  - v3.2: the cas and the flag are written when given, and region/stage are removed.
  - v3.0: region/stage come from the input, and the cas and flag are removed.
- `buildSurveyPayloadFromRemote` copies the three fields. A null value becomes `undefined`, so an untagged remote row stays untagged.
- `computePayloadCompletion`: for v3.2 it counts 1 for the version and 1 when `ibp_cas` is an integer from 1 to 4. The total stays 14.

## Deviations from Plan

**1. [Rule 2 - Correctness] An update with no version key on a v3.2 draft drops region/stage**
- **Found during:** Task 2
- **Issue:** The current form does not know about method versions yet and always sends region/stage. If the base payload's context were kept as-is, a v3.2 draft updated by that form would end up carrying region/stage, which breaks D-08.
- **Fix:** When the input has no version, the helper resolves the kept version. For v3.2 it drops region/stage. For v3.0 it writes them from the input as before. A test covers this case.
- **Commit:** `6c1d605`

**2. [Local narrowing] Two wire types differ from the package**
- `SyncBatchError = Partial<SyncResultError>`: the phone never relied on `code`/`message` being present.
- `SyncBatchOperation` requires `client_ref` and `payload`, as the phone has always sent them.
- These choices are recorded as decisions and are not package changes.

No package installs. No files outside the plan's list were touched.
