## Findings of the verification agents

- **Migration 5 root cause (the 7 against 6 factors).** `completion_rate` (`payload_completion`) is a percentage of 14 slots: the name, the method pair, the parcel and the ten factors. A draft with four context slots and six factors is 10 of 14, 71 percent, which the resume card rounded to 7; the detail counted 10 minus the package readiness `missing_factors`, which gives 6. A second difference (any non-empty value against what the package can score) also made them disagree. Fixed with one definition, `countFilledFactors`, stored in `local_surveys.payload_factors_filled`, migration 5 (`SCHEMA_VERSION` 4 to 5, backfilled from `payload_json`, never rewriting `payload_json` or `payload_completion`). The simulator database could not be opened, so which of the two paths produced the owner's exact 7 is not proven; the 71 percent arithmetic reproduces it.
- **Simulator session lost.** After a Release reinstall the simulator no longer held the logged-in session and it was not restored, because logging in is not done by the agent. Later simulator screenshots of logged-in screens were therefore not possible for the last builds.
- **Welcome screen unreachable.** The Welcome screen and its glass button cannot be reached without a fresh install and a login-free state, so it was never seen on the simulator or the phone.
- **Local failure of the API suite check-env-parity under macOS bash 3.2.** Known and local only (the script needs a newer bash); CI uses a Linux runner. Not related to this plan.
- **react-dom override mismatch to watch in CI.** Adding `@expo/ui` pulled `react-dom` 19.3.0 (peer `react ^19.3.0`) while the root `overrides` pins `react` 19.2.3 and Expo expects 19.2.3. `npm ls` reports no invalid entry because of the override and react-dom is never loaded on native. A root `"react-dom": "19.2.3"` override would be the clean fix; editing the root `package.json` overrides was refused during execution, so it is left for the owner or orchestrator.
- **expo-doctor 20 of 21.** The failing check lists seven pre-existing patch mismatches (`expo` 57.0.24 against ~57.0.27, `expo-constants`, `expo-image-manipulator`, `expo-image-picker`, `expo-location`, `expo-sqlite`, `react-native-worklets`), none involving `@expo/ui`. If CI's `mobile-build` blocks on expo-doctor they will show on the PR whatever D-28 does.
- **Gates at the tip (9ceb95a).** `npm run lint`, `npm run typecheck`, `npm run test:coverage:mobile` (229 suites, 2566 tests, thresholds hold), the `ibp-domain` suite (230 tests), `npm run format:check` (only the untracked `.claude/settings.local.json`) and `npm run audit:check` pass.
