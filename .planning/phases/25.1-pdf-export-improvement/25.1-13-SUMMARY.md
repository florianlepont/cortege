# Phase 25.1 Plan 13: Document shell Summary

The light print palette, the CSP, the embedded charter fonts, the base CSS of fixed A4 pages and the paginator that packs content blocks into pages, each with header, footer, literal "Page i / N" and, for a draft, the banner and watermark.

## What was built

- `buildPdfPalette()`: all 21 `PdfPalette` keys from `buildTheme("light")` (text, divider, panels, danger, error surface, score tones and track), `brandMapTokens.parcelSelected` and its fill, and `brandColors`/`mixWithWhite`/`withAlpha` for the watermark (forest at 0.07, the alpha confirmed visible and pale on both platforms in 25.1-07), the map canvas and the faint tints. No colour literal; same result whatever the device scheme.
- `styles.ts`: `PDF_CSP` (the exact policy) and `cspMetaTag()`; `fontFaceCss(fonts)` (one `@font-face` per font, name equal to the PostScript name, `data:font/ttf;base64` source; the family keeps only `[A-Za-z0-9_-]` and the data only base64 characters, so nothing read from disk can close the rule); `buildBaseCss(palette, layout)` with `@page { size: 595pt 842pt; margin: 0 }`, `.pdf-root { zoom: <scale> }` (the mechanism measured in 25.1-07, the only `zoom` in the sheet, `1` for an unusable scale), `.page` 595 x 840 with `overflow: hidden` and `page-break-after: always` except `section.page:last-of-type`, header, footer, banner, body and watermark classes, `print-color-adjust: exact`, font stacks ending in system sans-serif; `fontWarmupHtml(fonts, enabled = PDF_FONT_WARMUP)` (empty by default).
- `paginateBlocks(blocks, chrome)`: greedy packing into `(840 - 60 - 40 [- 24 draft]) * 0.92`; `breakBefore` opens a page unless the current one is empty; `keepWithNext` is checked on the whole run (heading chain plus the block after it, a `breakBefore` block ending the run); a block taller than the area gets its own page and never an empty one before it; non-finite heights count as 0; no blocks gives one empty page. Each page: `section.page[.page-draft]` with header (logo only when the data URI is a base64 PNG/JPEG, `Relevé IBP`, escaped site name), banner (draft), `page-body`, watermark (draft, after the body so cards cannot hide it), footer (`Cortège`, `Généré le ...`, `Page i / N` as literal text).
- 8 + 25 + 28 tests; the draft strip count equals `pageCount`, a submitted survey has none; hostile site name, generation text, logo URI, font family and font data are tested.

## Page geometry (design px, 595 x 840 block)

| Part | Value |
|------|-------|
| Margin left and right | 40 (content column 515) |
| Header box | top 16, height 34, border below; body starts at 60 (`PAGE_HEADER_HEIGHT`) |
| Draft banner | top 56, strip 18; body starts at 84 (`DRAFT_BANNER_HEIGHT` 24) |
| Footer box | bottom 14, height 22, border above; body ends at 800 (`PAGE_FOOTER_HEIGHT` 40) |
| Body | 515 x 740 (716 on a draft), `overflow: hidden` so an under-estimated block is cut at the footer rather than over it |
| Packing capacity | 680.8 (658.7 on a draft) for several blocks; a lone block may use the whole 740 / 716 |

## Deviations from Plan

None in behaviour. Notes:

- Palette tests mock `react-native` as `theme.test.ts` does (the plan said so). The structure gate (`structure.test.ts`) flagged a `title: "page-title"` entry of the class-name map as user-facing text; the key is `sheetName`.
- The plan listed `PAGE_HEADER_HEIGHT`, `PAGE_FOOTER_HEIGHT` and `DRAFT_BANNER_HEIGHT` as exports of `paginate.ts`; they are defined in `styles.ts` (the CSS reads them) and re-exported by `paginate.ts`, so both import paths work.
- `export-settings.ts` already has a `PDF_PAGE_FILL_FACTOR` of 0.9 (plan 07, "text layout plans decide"); the plan's `PAGE_FILL_FACTOR` of 0.92 in `paginate.ts` is the one used. The older constant is now unused by the paginator.
