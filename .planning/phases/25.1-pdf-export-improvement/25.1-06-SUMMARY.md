# Phase 25.1 Plan 06: Parcel history cache Summary

The last successful parcel history is now kept in `local_meta` under `parcel_history:<PARCEL_ID>` (with its fetch date, 50 items at most, no migration), written by the history hook on every successful load and deleted with the rest of the local data, so the PDF trend can print offline.

## What was built

- `mobile/src/storage/parcel-history-cache.ts`: `PARCEL_HISTORY_KEY_PREFIX` ("parcel_history:"), `PARCEL_HISTORY_MAX_ITEMS` (50), `parcelHistoryKey` (trim, upper-case), `CachedParcelHistory { fetched_at, items }`, `saveParcelHistoryCache(parcelId, items, fetchedAt = now)` (upsert, keeps the last 50 items since the API order is oldest first), `loadParcelHistoryCache(parcelId)` (guarded parse: invalid JSON, non-object, missing `items` array or non-string `fetched_at` read as null; items without a string `survey_id` are dropped). Every function catches its own errors.
- `clearLocalIbpData` (surveys.ts) deletes `parcel_history:` rows in its transaction with `instr(key, ?) = 1`.
- `useParcelSurveyHistory`: after the stale-request guard, `void saveParcelHistoryCache(parcelId, items).catch(() => undefined)` with the same items the state receives. Offline, error, missing token and stale responses never write. Hook return values are unchanged.
- Tests: 9 sqlite tests for the store (including the purge leaving `parcelXhistory:1` and `map_preference`, and a database failure), 5 new hook tests (write once with items, empty list on a non-array response, no write on failure/offline/no token, no write when stale, a rejected write leaves the state untouched).
