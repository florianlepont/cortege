# Phase 25.1 Plan 15: Data loader and export runner Summary

The data side and the file side of the new PDF export: an offline-first loader that turns the screen's
`SurveyExportInput` into `SurveyExportData` without ever failing for an optional piece, and a runner
that prints A4, renames the file under `<cache>/exports/`, shares it and removes old exports at the
next export. The old `survey-pdf-export.ts` facade is untouched (plan 25.1-16 switches the call site).

## What was built

- `listSurveyPhotosInCaptureOrder(surveyId)` in `storage/surveys.ts`: same columns as
  `listLocalAttachments`, images only, `ORDER BY created_at ASC, id ASC`. No schema change. 4 sqlite
  tests (shuffled insert order and `updated_at`, non-image and other survey, tie on `created_at`, empty).
- `assembleSurveyExportData(input, deps)`: the photo branch, the map branch (cached outline, optional
  bounded read, frame, snapshot) and the factors, history and asset reads run in one `Promise.all`;
  each is wrapped in its own fallback that logs `logStatusDetail("surveyExport.assemble", { piece, error })`.
  Frame: `fitFrameToBounds(bounds, MAP_FRAME_SIZE, { paddingRatio: 0.12, zoomRange: OFFLINE_ZOOM_RANGE })`,
  or zoom 16 around the coordinates with no outline. `coordinates` is the display location, else the
  centre of the outline bounds. 37 tests (100% statements and lines).
- `run-export.ts`: `printSurveyPdf` (595 x 842, zero margins), `moveToExportName` (mkdir with
  `intermediates`, delete the target `idempotent`, move), `cleanStaleExports`, `shareSurveyExportPdf`
  (`application/pdf`, `com.adobe.pdf`, `shareDialogTitle(siteName)`), `exportAndShareSurveyPdf(input, deps?)`:
  cleanup, assemble, `buildSurveyExportHtml`, print, iOS-only page-count check logged with
  `logStatusDetail("surveyExport.pageCount", { built, printed })`, name from `buildExportFileName`,
  move, share. Print and share errors reject. 24 tests, including a whole offline flow with fake loaders
  and `fetch` spied (never called).

## Notes for the next plans

- **25.1-16 (call site):** the screen builds a `SurveyExportInput` (it includes `apiUrl` and `accessToken`)
  and calls `exportAndShareSurveyPdf(input)`; no second argument in production. It returns
  `{ shared }`; print and share errors reject, so the screen keeps its alert. The module needs
  `react-native` `Platform` (tests mock it: `jest.mock("react-native", () => ({ Platform: { OS: "ios" } }))`).
- **Snapshot without an outline is wasted work:** with a known location but no outline the loader still
  decides and takes a basemap (the plan's behaviour), but `buildMapBlock` returns the "no outline" note
  whenever `polygons` has no bounds and never uses the basemap. If a snapshot ever costs time there
  (up to 12 s online), skip it in `loadMapPiece` or print the basemap alone in `map-section.ts`.
- `fetchParcelStatuses` is called with `zoom: 16` and a +-0.001 degree box; no `year` is passed.
- The runner keeps the printed file in `exports/` after sharing; only the next export removes it
  (one hour rule, the file just shared is never touched).
