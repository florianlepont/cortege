### `src/storage/parcel-history-cache.ts` (service, CRUD on local_meta)

**Analog:** `src/storage/search-recents.ts` (the whole file, 82 lines). Copy: exported key constant, best-effort functions that catch their own errors, JSON parse guarded, upsert SQL.

**Upsert and read** (l.28-50):
```typescript
async function writeRecents(recents: string[]): Promise<void> {
  const db = await getDb()
  await db.runAsync(
    `INSERT INTO local_meta (key, value, updated_at)
     VALUES (?, ?, ?)
     ON CONFLICT(key) DO UPDATE SET
       value = excluded.value,
       updated_at = excluded.updated_at`,
    [SEARCH_RECENTS_KEY, JSON.stringify(recents), new Date().toISOString()],
  )
}
export async function loadSearchRecents(): Promise<string[]> {
  try {
    const db = await getDb()
    const row = await db.getFirstAsync<{ value: string }>(
      `SELECT value FROM local_meta WHERE key = ?`,
      [SEARCH_RECENTS_KEY],
    )
    return parseRecents(row?.value)
  } catch {
    return []
  }
}
```
Adapt: key is `parcel_history:${parcelId}` (a prefix `PARCEL_HISTORY_KEY_PREFIX`), value `{ fetched_at, items: ParcelSurveyHistoryItem[] }`, parse guard returns `null` on corrupt value. Header comment style (l.3-9) explains "convenience data, no migration, deleted by clearLocalIbpData".

**Purge** in `src/storage/surveys.ts` `clearLocalIbpData` (l.525-539), inside the existing transaction, add after the `IN (?, ?, ?)` delete:
```typescript
await tx.runAsync(`DELETE FROM local_meta WHERE key LIKE 'parcel_history:%'`)
```
Import the prefix constant like `SEARCH_RECENTS_KEY` is imported there. No SQLite migration (schema stays at 5).

**Test:** copy `src/storage/search-recents.sqlite.test.ts` (l.1-60: `createNodeSqliteDb`, `jest.mock("expo-sqlite")`, `initLocalDb` in `beforeAll`, `DELETE FROM local_meta` in `beforeEach`, `putRaw` for corrupt value, and the l.115 `clearLocalIbpData deletes ...` case).

### D-12 stored details: `src/hooks/useSurveyForm.ts`, `FactorChipsInput.tsx`, `FactorDetailScreen.tsx`

**Current state:** B, I, J use `FactorChipsInput`, which stores only the derived count. Its header (l.28-35 of `src/ui/FactorChipsInput.tsx`) says the domain reads only the count; the selection lives in local `useState` and is re-seeded as "the first N options are pre-checked" (l.52-57). So selection is lost on reopen. F is a plain numeric `trees_per_ha`; H a segmented `class_score`.

**Payload write** (`useSurveyForm.ts` l.246-247 for B; I/J l.272-276):
```typescript
const bStrata = toFiniteNumberInRange(factorB.strata_count, { min: 0, integer: true })
if (bStrata !== null) payload.B = { strata_count: bStrata }
...
if (i !== null) payload.I = { type_count: i }
```
**Payload read** (`applyDraftToForm`, l.323): `setFactorB({ strata_count: toTextNum(factorBObj.strata_count) })`, via `asObject(factors.B)`.
**Field plumbing** (factorSections, l.431-440): `{ label, value, onChange: (v) => setFactorB((prev) => ({ ...prev, strata_count: v })), required, error, ...touchState("B", ...) }`.
**Variant table** (`FactorDetailScreen.tsx` l.30-52): `B: [{ kind: "chips", options: fr.factorInput.strataOptions, countLabel }]`, `I: aquaticHabitatOptions`, `J: rockyHabitatOptions`, `H: segmented continuityOptions`. Option values come from the catalogue (`fr.factorInput.*Options`).

Plan shape: store the selected option values next to the count (for example `B: { strata_count, strata_selected: string[] }`; the planner fixes the names), have `FactorChipsInput` accept an initial selection instead of re-deriving it from the count, keep `strata_count`/`type_count` as the scored value so `@cortege/ibp-domain` is untouched. `factors` is `Record<string, unknown>` on the wire (`packages/ibp-domain/src/contract/survey.ts` l.52, 67, 84; `contract/sync.ts` l.67), so extra keys travel without a type change; verify the API does not reject unknown keys (not checked here). Old surveys: print what exists, no placeholders. The PDF reads the new keys in `factor-fields.ts` and maps option values to catalogue labels.

DMH groups (F) and H evidence have no existing input: closest analogs are `FactorChipsInput` (multi-select) for DMH and `FactorSegmentedInput`/`FactorField` plumbing for H. Treat as no exact analog.

## Shared Patterns

### Catalogue-only text and escape
**Source:** `src/app/survey-pdf-export.ts` l.14, 32-39. **Apply to:** every `survey-pdf/*` builder: `const t = fr.surveyExport`, one `escapeHtml`, no French literal in code (`structure.test.ts` flags `label/title/...` string props outside `src/i18n`; name fields `caption`, `heading`, `name`).

### Best-effort storage and optional pieces never throw
**Source:** `src/storage/search-recents.ts` (try/catch returning empty). **Apply to:** `parcel-history-cache.ts`, `assemble-export-data.ts` (each optional piece returns null/[] and records an omitted code).

### Domain rules from the package only
**Source:** `survey-pdf-export.ts` l.3 (`FACTOR_KEYS`), `src/app/ibp-scoring.ts`, `ibp-display.ts`. **Apply to:** factor-fields, score-section, chart, trend.

### Colours through tokens only
**Source:** `src/app/theme.ts` (`buildTheme("light")`), `brand-tokens.ts`, `visual-tokens.ts`. **Apply to:** palette/styles/SVG builders. No `#` or `rgba(` literals elsewhere (ESLint).

### Offline guarantee
**Apply to:** loader and HTML: no `fetch` unless online and time-bounded; CSP meta; data: URIs only; snapshot raced against an 8 s timeout (Android snapshot promise never rejects).

### Screen size gate
`SurveyDetailScreen.tsx` (333 lines) must stay under 400 (`structure.test.ts`): logic goes to `useSurveyPdfExport.ts`.
