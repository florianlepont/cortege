# Phase 25.1 Plan 09: Factor cards A to J Summary

The ten factor cards of the sheet are built: `factor-fields.ts` maps every stored observation to a printed line per method, and `factor-section.ts` turns them into packable blocks with the class chips, retained class, points, scale line and the missing-factor marker.

## What was built

- `buildFactorObservations(factor, rawFactors, { method, points })` returns `ObservationLine[]` (`caption`, `value`, `items?`, `note?`). A: genera as "Hêtre (Fagus)" with the not-counted suffix per cas, count line, legacy `native_genus_count` (also `autochthonous_genus_count` and `count`, the domain's key order), cover from A else the legacy B location, cap note. B to J follow the plan; per-hectare values are display arithmetic only. Detail arrays (B strata, F groups, H sources, I/J types) go through `readSelection` and `selectionLabel` with the survey's method version, unknown codes are dropped, and a survey saved before 25.1-04 prints its counts only.
- `buildFactorBlocks(data, palette)` returns 12 blocks: `factor-heading-stand` (keepWithNext), `factor-A` to `factor-G`, `factor-heading-context` (keepWithNext), `factor-H` to `factor-J`. Each card: letter, catalogue title, observation lines on the left, a 170-unit right column with one chip per `allowedScoresFor(factor)` (only the retained points highlighted), the retained class and `pointsOutOfFive`, then the `Barème` line from `scaleLines[methodKey][factor]`.
- A factor whose entry is absent or the "Not filled" sentinel shows `factors.missing` with an inline `palette.alert` colour, no highlighted chip, and still prints its raw observations.
- Height estimate in design units (`FACTOR_CARD_BASE_HEIGHT = 86`, then observation rows, wrapped rows, item rows and scale-line rows, all as named constants with comments).
- `factorSectionCss(palette)`: classes all prefixed `factor-`, colours only from the palette, fonts from `PDF_FONT_FAMILIES`, no CSS columns, no 1 px filled divs (borders and flex only, per the 25.1-07 iOS findings).
- 40 tests (24 + 16): v3.2 and v3.0 fixtures, D-12 details, legacy surveys, hostile values, escaping, NaN, absent factors, height growth, CSS hygiene.

## Notes for the next plans

- The cards use `display: flex` for the two-column body (iOS WebKit supports it; only `column-count` was found unsupported). Not yet printed on a device: the first real render is in the assembly plans, where the height constants (`OBS_CHAR_WIDTH`, `SCALE_CHARS_PER_LINE`, row heights) should be checked against a rendered page and tuned in `factor-section.ts` if a card overflows its estimate.
- The cards assume a content width of 515 design units (same as `MAP_FRAME_SIZE`); a different page margin changes `OBS_WIDTH` and the 170-unit result column.
- `factorSectionCss` is not yet concatenated into the document: the style assembler plan adds it. Block margin (8) is included in each card height, so the packer must not add its own gap.
- The missing marker uses an inline `style="color: ..."` (the CSP allows `style-src 'unsafe-inline'`), and the class `factor-missing` also sets the colour.
- `useLocalDraftSummary`'s `NOT_FILLED_CLASS` is duplicated as a local constant on purpose (that module imports React and storage); keep both in step.
