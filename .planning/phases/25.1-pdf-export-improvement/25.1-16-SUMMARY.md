## Deviations from Plan

**1. [Rule 1 - Bug, owner-requested via the executor brief] Wasted basemap snapshot without an outline**
- **Found during:** plan 25.1-15 (noted in its summary), fixed here on the owner's instruction
- **Issue:** with a known location but no parcel outline, `loadMapPiece` still decided and took a
  basemap (up to 12 s online) although `buildMapBlock` returns its "no outline" note and ignores the
  basemap when `polygons` has no bounds.
- **Fix:** `loadMapPiece` computes the outline bounds once and takes the snapshot only when bounds
  exist; the unreachable "zoom 16 around the location" frame branch and `LOCATION_ZOOM` were
  removed. `data.coordinates` is still the display location (else the outline centre). The test
  "frames zoom 16 around the location when there is no outline" became "takes no snapshot when there
  is no outline" (decide and take not called, `map.basemap` null, coordinates kept); the "network
  check throws" test now gives a cached outline so it still reaches the basemap decision.
- **Files modified:** `assemble-export-data.ts`, `assemble-export-data.test.ts`
- **Commit:** 2e4fa2e8

**2. [Rule 1 - Bug avoided] Region and stage source order**
- The plan says "region and stage from `detail` else `localDraftMeta`". For an editable draft the
  local payload holds the latest edits (the same rule as `resolveScoringContext` and
  `useSurveyDetailData`), so reading the possibly stale server detail first could print a region the
  member already changed. The mapper therefore reads local first for drafts and detail first for
  submitted surveys (tests cover both). Year, version number and date still read the detail first.
