## Summary

The current export (`mobile/src/app/survey-pdf-export.ts`, 147 lines) is a pure HTML builder plus `Print.printToFileAsync` and `Sharing.shareAsync`. It prints one class label per factor and the raw method tag. The rebuild is mostly a data-assembly and layout problem, not a library problem: every library needed is already installed at the right SDK-57 versions (`expo-print` 57.0.2, `expo-sharing` 57.0.22, `expo-file-system` 57.0.7, `expo-image-manipulator` 57.0.20, `@maplibre/maplibre-react-native` 11.4.0, `react-native-svg` 15.15.4). The only dependency to declare is `expo-asset` (already in the lockfile at 57.0.18 through `expo`) to turn the bundled fonts and logo into base64.

Three findings drive the plan. (1) The raw observations ARE available on the phone: `getLocalSurveyDraft(id).factors` holds `genera[]`, `native_cover_percent`, `strata_count`, `bmg/bmm/tgb/gb_count`, `surface_ha`, `trees_per_ha`, `open_flowering_percent`, `class_score`, `type_count`. But the form never stores which strata tiers (B) or which aquatic/rocky types (I, J) were ticked, nor the 15 DMH groups (F), nor H's evidence: only the counts survive, so "same information as the CNPF sheet" is only attainable down to the counts. Photos carry no factor link (metadata is `source`, file name, sizes), so "grouped by factor" is not possible without a data change. (2) Two of the data pieces the owner asked for have no offline cache today: the parcel history (fetched from the API, held in React state, cleared when offline) and the parcel geometry (only exists on the phone for downloaded offline areas, in `offline_area_parcels`). The cheapest closure is a `local_meta` cache for the history (no SQLite migration, same pattern as `search_recents`) and a geometry lookup order of offline-area cache first, then one short bounded fetch, then "no map". (3) The native snapshot API exists and is the right one: `StaticMapImageManager.createImage({ mapStyle, center, zoom, width, height, output: "file" })` renders from a style without any mounted view. On Android its native implementation never rejects on error (the error callback only logs), so a `Promise.race` timeout is mandatory. Parcel polygons are not in the snapshot: they are drawn as an SVG overlay computed from the same Web Mercator projection, which also makes the offline fallback (outline without basemap) the same code path with the image left out.

The largest risk is rendering parity between expo-print on iOS (WKWebView + `UIPrintPageRenderer`, CSS px is about 1 pt) and on Android (Chromium print adapter, CSS px likely about 0.75 pt), plus unreliable CSS page-break and repeating header/footer behaviour on iOS. The recommendation is to not depend on any of it: build explicit fixed-size A4 "page" blocks in the builder, each carrying its own header, footer, "Page i / N" and watermark, joined with `page-break-after: always`, with a per-platform layout scale injected by the thin runtime wrapper. A one-day device spike (iOS simulator + Android emulator `Pixel_8`, both available on this machine; `pdffonts`, `pdfimages`, `pdfinfo` and `pdftoppm` are installed) must calibrate this before the visual work starts.

**Primary recommendation:** Keep `buildSurveyExportHtml` pure by splitting it into small builders under `mobile/src/app/survey-pdf/`, assemble all data in one async, offline-safe loader that never throws for a missing optional piece, render fixed A4 page blocks with base64-inlined fonts, logo, JPEG photos and one JPEG map snapshot with an SVG parcel overlay, and start with a device spike plan that settles page size, fonts, image weight and snapshot behaviour before anything else is built.

### Pattern 1: Native snapshot of the basemap, polygons as SVG (answers question 1)

**What:** `StaticMapImageManager.createImage` renders a style to a PNG without any mounted view. Pass `center` and an integer `zoom` (not `bounds`) so the pixel mapping is known and the zoom stays inside the offline pack range (`OFFLINE_MIN_ZOOM` 13 to `OFFLINE_MAX_ZOOM` 17, `mobile/src/map/offline-packs.ts`). Use `output: "file"`, then pass the file through `ImageManipulator` to a JPEG at about 1100 px wide (the PNG is at device pixel ratio, up to 3x). Draw parcels in an SVG `viewBox="0 0 W H"` layered over the `<img>` with the same W by H, projected with the same Web Mercator formula.
**When to use:** the parcel map section (D-06), both online and with an offline pack.
**API facts [VERIFIED: node_modules/@maplibre/maplibre-react-native/src and native sources]:**
- Signature: `createImage({ mapStyle: string | object, width, height, output: "base64" | "file", logo?, center?, zoom?, bearing?, pitch? } | { ..., bounds: [west, south, east, north] })`. Output is always PNG. The `mapStyle` object form is JSON-stringified; a `file://` style URI (the offline composite style written by `writeOfflineStyle`) is accepted (`MLRNUtils styleURLFromMapStyle` on iOS, `Style.Builder().fromUri` on Android).
- iOS (`MLRNStaticMapModule.mm`): `MLNMapSnapshotter` started on the main queue; on `error` the promise is rejected (`"createImage"`); output is a temp file or base64. Image scale follows the screen scale.
- Android (`MLRNStaticMapModule.kt`): `MapSnapshotter` with `withPixelRatio(1dp in px)`; the `SnapshotReadyCallback` resolves the promise, but the error handler only does `Log.w` and removes the snapshotter: **the JS promise never settles on error**. A timeout is mandatory.
- `width`/`height` are logical points; the PNG is `width*ratio` by `height*ratio` pixels on both platforms, so one geographic extent for both. `[ASSUMED]` identical extents on iOS and Android, to confirm in the spike by drawing a known coordinate.
- `logo: false` (default). Attribution is not drawn: print "Source : IGN" yourself (`ORTHO_STYLE` already declares that attribution string).
**Behaviour with offline packs `[ASSUMED]`, to verify in the spike (airplane mode):** the snapshotter reads the same native cache as the live map; a pack created for the style covers the snapshot if centre and integer zoom lie inside the pack. A remote style URL that cannot be fetched fails (iOS rejects, Android hangs until the timeout). Missing individual tiles typically render as an empty background, not an error. Therefore decide the basemap yourself before calling it (see decision order below) instead of relying on the call to fail.
**Decision order for the style (pure function `decideBasemap`):** (1) `findReadyOfflineAreaForPoint(lat, lng)` returns a ready area AND `offlineStyleExists(dir, "map", false)` is true: use `offlineStyleUri(dir, "map", false)` (the LIGHT variant: print is always light, never the `-dark` file; it already carries the cadastre raster); (2) else if online: `PLAN_IGN_STYLE_URL` (via `mapStyleFor("map")`); (3) else: no image, SVG outline only. Never choose the satellite basemap for print (ink and size).
**Triggering without blocking:** `createImage` is promise based and the heavy work is native; start it in parallel with photo processing (`Promise.all`), race it against an 8 s timeout, and treat any rejection or timeout as "no basemap". Show a busy state from the screen hook; the share action must not be tappable twice.
**Example:**
```typescript
// Source: @maplibre/maplibre-react-native 11.4 StaticMapManager.ts + MLRNStaticMapModule.{mm,kt}
import { StaticMapImageManager } from "@maplibre/maplibre-react-native"

const SNAPSHOT_TIMEOUT_MS = 8000

export async function takeBasemapPng(input: {
  mapStyle: string
  center: [number, number] // [lng, lat]
  zoom: number // integer, 13..17
  width: number
  height: number
}): Promise<string | null> {
  let timer: ReturnType<typeof setTimeout> | undefined
  try {
    return await Promise.race([
      StaticMapImageManager.createImage({ ...input, output: "file" }),
      new Promise<null>((resolve) => {
        timer = setTimeout(() => resolve(null), SNAPSHOT_TIMEOUT_MS)
      }),
    ])
  } catch {
    return null // iOS rejection: same degradation as a timeout
  } finally {
    if (timer) clearTimeout(timer)
  }
}
```
Add `StaticMapImageManager` to `mobile/test/maplibre.mock.ts` (it currently exports `Map`, `Camera`, layers and `OfflineManager` only) so loader tests can drive success, rejection and a never-settling promise with fake timers.

### Pattern 2: Web Mercator projection for the SVG overlay (pure, unit-tested)
**What:** with MapLibre's 512 px world, `X(lng, z) = (lng + 180) / 360 * 512 * 2^z` and `Y(lat, z) = (0.5 - ln((1 + sin φ) / (1 - sin φ)) / (4π)) * 512 * 2^z`. For a snapshot of `W x H` centred on `(cLng, cLat)` at integer zoom `z`, a point maps to `(X(lng) - X(cLng) + W/2, Y(lat) - Y(cLat) + H/2)`. Fit zoom: `z = clamp(floor(log2(min(W*(1-2p)/dx0, H*(1-2p)/dy0))), 13, 17)` where `dx0`, `dy0` are the bbox size in pixels at zoom 0. Metres per pixel at the centre: `40075016.686 * cos φ / (512 * 2^z)`; pick the largest of 50, 100, 200, 500, 1000, 2000 m that fits within a quarter of the width for the scale bar. North is up (bearing 0). A checked run for a 365 m by 330 m bbox in a 520 x 320 frame gave `z = 15`, 1.57 m/px, corners at (143, 266) and (377, 54): inside the frame. `[ASSUMED]` that the native snapshot uses the same 512 convention for `zoom`; the spike must confirm by overlaying the cadastre lines in the offline style on the SVG polygons (they must coincide).
**Why integer zoom:** keeps tile requests on the levels the offline pack stored (raster 256 px sources need zoom+1 tiles, covered by the pack's range).
**Outline fallback:** same projection, but with no `<img>`: draw the polygons and the scale/north arrow on a pale canvas, bbox-fit without the 13..17 clamp (any zoom is fine without tiles, use a continuous fit and a `metres per pixel` from it).
**Polygon source:** reuse `buildParcelFeatureCollection(items, selectedIds)` from `map/maplibre/parcel-features.ts` (validates and filters coordinates) and project its rings. Colours from `brandMapTokens.parcelSelectedFill` and `parcelSelected`, not new literals.

### Pattern 3: Fixed A4 page blocks (answers question 2)
**What:** the builder produces `pageCount` page `<section class="page">` blocks, each exactly the page size, each with header (logo, site, "Relevé IBP"), footer (generation date, "Page i / N", app name), the draft banner and watermark when `isDraft`. Content is a list of blocks with an estimated height; `paginate.ts` packs them greedily with a 90 % fill factor and starts a new page for the photo grid, the map and the trend. Pages are joined with `page-break-after: always` and `.page { height: <842 minus 2 px>; overflow: visible }` (a page that is exactly the paper height risks a blank trailing page after rounding `[ASSUMED]`).
**Why:** this removes the dependency on repeating `position: fixed` headers, `@page` margins and CSS counters, which differ between WebKit and Chromium.
**Platform profile:** the runtime wrapper passes `{ platform, layoutScale }` into the pure builder (`layoutScale` 1 on iOS, to be measured on Android, expected 1.333). Apply it once on the root container (`zoom` or a CSS custom property multiplier). Design all dimensions in "A4 at 72 dpi" units (595 by 842).
**Return value check:** `printToFileAsync` returns `numberOfPages`; on iOS compare it to the builder's `pageCount` and send a mismatch to `logStatusDetail` (a mismatch means an overflow or a blank page). On Android the value is a height heuristic and is not reliable. [VERIFIED: expo-print Android `PrintPDFRenderTask.kt`: `numberOfPages = 1 + contentHeight / pageHeight`]

### Pattern 4: Per-page header, footer, banner and watermark inside each page block
**What:** header and footer markup is generated per page, so "Page 2 / 7" is literal text. The draft banner is a coloured strip under the header ("Brouillon, non soumis"). The watermark is an absolutely positioned rotated text layer (`transform: rotate(-30deg)`) in a pale colour from `withAlpha(brandColors.forest, 0.07)` placed above the content with `pointer-events` irrelevant, so card fills cannot hide it. Use a plain rgba colour rather than the CSS `opacity` property on text `[ASSUMED]` safer across Skia PDF and CoreGraphics.

### Pattern 5: Offline-safe assembly with injectable dependencies
**What:** `assembleSurveyExportData(input, deps)` takes `deps` (db readers, `Network`, `StaticMapImageManager`, `ImageManipulator`, `Asset`, clock) so Jest drives every branch with fakes. Each optional piece returns `null`/`[]` on any failure and records a code in `data.omitted` (for example `"map"`, `"history"`, `"photo:3"`), which the builder renders as a one-line note from the catalogue. The export itself never throws for a missing optional piece, only for `printToFileAsync` or `shareAsync` failures.

### Pattern 6: File naming and rename (answers question 3)
**What:** `printToFileAsync` writes `<cacheDirectory>/Print/<uuid>.pdf`. Move it with `FileSystem.moveAsync({ from, to })` to `<cacheDirectory>exports/Cortege-IBP-<slug>-<year>[-brouillon].pdf` after `makeDirectoryAsync(exportsDir, { intermediates: true })` and `deleteAsync(to, { idempotent: true })`. iOS `moveAsync` removes the destination first; Android uses `File.renameTo`; deleting the target first makes both safe. [VERIFIED: expo-file-system `ios/Legacy/FileSystemLegacyModule.swift` line 140 `removeFile(... idempotent: true)`, Android `FileSystemLegacyModule.kt` `renameTo`] Android sharing goes through `FileProvider` with `<cache-path path=".">`, so any file under `cacheDirectory` is shareable, and the shared file name is the visible name. iOS shows the file name in the share sheet.
**Slug rule (pure `buildExportFileName(siteName, year, isDraft, fallbackDateIso)`):** NFD-normalise, strip combining marks, replace every run of non `[A-Za-z0-9]` with a single `-`, trim `-`, cap at 40 characters (cut at a `-` when possible), empty result becomes `releve`; year = `observationYear`, else the year of `dateIso`, else the segment is omitted (no `unknown`); `-brouillon` suffix when `isDraft`; always ASCII so no `/`, `..`, quotes or control characters can reach a path. Same site and year overwrites the previous export (acceptable, deleted first).

### Anti-Patterns to Avoid
- **`file://` image `src` in the HTML.** iOS WKWebView cannot read local asset URLs from `loadHTMLString`, and the Android WebView is loaded with a null base URL. Inline everything as `data:` URIs. [CITED: docs.expo.dev/versions/v57.0.0/sdk/print/: "printing from HTML source doesn't support local asset URLs (due to WKWebView limitations)"]
- **`useMarkupFormatter`.** It does not display images. [CITED: same page]
- **Relying on `position: fixed` or `@page` margins for header/footer.** See Pattern 3. iOS margins exist only as the `margins` option, Android takes margins from `@page`. [CITED: same page]
- **Reading the dark map style for print.** `useMapStyle` returns the recoloured dark style in dark mode; the export must pick the light style explicitly.
- **Importing `react-native` (via `Platform`) inside the pure builder.** Inject `platform` and `layoutScale`.
- **A second escape function or ad hoc string concatenation of user text.** Everything user-controlled (site name, parcel ids, genus display names, observer name) goes through `html.ts` `escapeHtml`.

## Common Pitfalls

### Pitfall 1: Android CSS pixel is not an iOS point
**What goes wrong:** the same HTML renders at about 75 % of the page width on Android (Chromium prints at 96 CSS px per inch, 595 pt = 793 px) and fills the page on iOS (WebKit print layout at about 1 px per pt). `[ASSUMED]` from Chromium and WebKit print behaviour; the existing Phase 19 export used 24 px padding and was only eyeballed. Not documented by Expo.
**How to avoid:** spike first. Inject `layoutScale` per platform from the runtime wrapper; declare `@page { size: 595pt 842pt; margin: 0 }` for Android (docs: Android margins come from `@page`; iOS margins only from the `margins` option, leave zero).
**Warning signs:** right-hand margin visible on one platform only; text size differs between the two PDFs.

### Pitfall 2: CSS page breaks and repeating headers are unreliable on iOS
**What goes wrong:** forum reports of `printToFileAsync` ignoring `page-break-inside: avoid` on iOS while Android is fine; `position: fixed` headers get shifted by page margins. [CITED: forums.expo.dev thread "printToFileAsync not respecting CSS page breaks" (search result; page not retrievable)]
**How to avoid:** Pattern 3 (explicit page blocks, `page-break-after: always`, no reliance on `avoid`). Photos in fixed cells (fixed size `object-fit: contain`).
**Warning signs:** `numberOfPages` differs from the builder's `pageCount`; a block split across two pages; blank last page.

### Pitfall 3: Custom fonts may not be ready when iOS prints
**What goes wrong:** `ExpoWKPDFRenderer` starts rendering on `webView(_:didFinish:)` and does not wait for `document.fonts.ready` `[VERIFIED: ios/ExpoWKPDFRenderer.swift]`; a `@font-face` whose source is a `data:` URI usually loads at once but a race is possible `[ASSUMED]`, giving the system font in the PDF.
**How to avoid:** embed only the cuts actually used (Sora-ExtraBold, Sora-Medium or SemiBold, Jost-SemiBold, Jost-Regular, Sora-Light for the numeral), name the CSS family exactly like the PostScript names in `brandTypography` (`Sora-ExtraBold`...), and verify with `pdffonts` on the generated file in the spike. If a race shows, add a hidden text node per font in the first page so the font is requested during layout.
**Warning signs:** `pdffonts` lists Helvetica/SFNS instead of Sora and Jost.

### Pitfall 4: PDF size explodes with photos on iOS
**What goes wrong:** WKWebView print draws decoded bitmaps; CoreGraphics may embed them losslessly (Flate) instead of keeping the JPEG `[ASSUMED]`, so 24 photos at 1000 px could exceed 20 MB. Android Skia usually keeps JPEG.
**How to avoid:** size photos to the printed size (cell about 250 pt wide: 700 to 800 px long edge is already about 190 dpi), JPEG compress 0.6 to 0.7, sequential processing, a cap (start at 24 photos, shown as "N photos sur M" when capped), and measure with `pdfimages -list` (encoding column) and file size in the spike. Stored photos are already at most 2048 px, JPEG 0.7 (`MAX_PHOTO_EDGE_PX`, `PHOTO_JPEG_QUALITY` in `storage/attachments.ts`), so a second pass is a downscale, not a first compression.
**Warning signs:** PDF over 10 MB; generation over 15 s; memory warnings.

### Pitfall 5: Android can finish loading before large data-URI images decode
**What goes wrong:** `onPageFinished` triggers the print write immediately `[VERIFIED: PrintPDFRenderTask.kt]`; images in a very large HTML string might be missing `[ASSUMED]`.
**How to avoid:** keep each image small, keep total HTML under about 8 MB (cap photos), test the 24-photo worst case on the emulator, and add an `img` `width`/`height` so layout does not depend on decode.

### Pitfall 6: `StaticMapImageManager` hangs forever on Android errors
**What goes wrong:** `MLRNStaticMapModule.kt` logs the snapshot error and never settles the promise. Offline with a remote style, or a bad style, freezes the export spinner. [VERIFIED: source]
**How to avoid:** `Promise.race` timeout (8 s), decide the basemap before calling (Pattern 1), and the export continues without the image. Serialise snapshots (one at a time); iOS docs for the sibling Mapbox snapshotter say one snapshot at a time.

### Pitfall 7: Catalogue and gates that this phase touches
- `catalogue-dash.test.ts` keeps `survey-export.ts` out of scope by file name (`OUT_OF_SCOPE`) and asserts that no catalogue file list contains it (`expect(files.some(... "survey-export.ts")).toBe(false)`). D-08 requires removing the `"—"`; the cleanest move is to delete the exception: remove `OUT_OF_SCOPE`'s entry, flip that assertion to `true`, and update the comments, `CLAUDE.md` ("`survey-export.ts` excepted") and `docs/design/charte-graphique-etats-sauvages-spec.md` line 572. The existing test `catalogue.test.ts` also requires non-empty strings.
- The new modules in `src/app/survey-pdf/` are scanned by the em-dash gate (only comments are exempt). Write arrows, dots and separators as `·` or words, never U+2014 or `&mdash;`.
- `structure.test.ts` `findUserFacingLiterals`: an object property named `label`, `title`, `subtitle`, `placeholder`, `description` or `message` (`OBJECT_LABEL_PROPS` in `mobile/scripts/structure-report.js`) holding a string literal containing a letter is flagged outside `src/i18n`; JSX text, `Alert.alert` strings and status messages likewise. Fixture objects in `*.test.ts` files are exempt. In the new modules name such fields `caption`, `heading` or `name`, and take every French word from `fr.surveyExport` (and the existing catalogue sections).
- `fonts.test.ts` scans `fontFamily:\s*"..."` string pairs in source: CSS written as `font-family: Sora-ExtraBold` inside a template string does not match, but any JS object `fontFamily: "X"` must name an embedded file.
- `layers.test.ts` is about styles (`borderCurve`, gradient plus border), NOT import rules (the brief assumed otherwise); the HTML builders contain no such object keys.
- Coverage ratchet (`jest.unit.config.js`): `./src/app/` has thresholds (statements 91, branches 80, functions 97, lines 95) that the new pure modules must raise rather than lower; native wrappers are tested through the injected fakes.

### Pitfall 8: Test environment for `buildTheme`
`theme.ts` imports `react-native` (`useColorScheme`). Tests of any module that imports it need `jest.mock("react-native", () => ({ useColorScheme: () => "light" }))` as `theme.test.ts` and `visual-tokens.test.ts` do. Put the colour access in `palette.ts` so only that file (and the tests that import the builder) need the mock, or pass the palette into the builders as an argument and build it once in `build-html.ts`.

### Pitfall 9: Breaking the offline invariant
`fetchPublicParcelStatuses` and the style fetch are the only network paths. Both must be optional, time-bounded and off when offline; add a Content-Security-Policy meta (`default-src 'none'; img-src data:; font-src data:; style-src 'unsafe-inline'`) to the HTML so the print WebView can never fetch anything and any unescaped value cannot load a remote resource. A Jest test asserts the CSP and the absence of `http` in the HTML.

### Pitfall 10: Busy state and double taps
Today `handleShare` has no busy state (an `Alert` on failure only). The new export takes several seconds: add `exporting` to a `useSurveyPdfExport` hook, ignore taps while running, and show a progress indication (catalogue string). `Sharing.shareAsync` throws if a share is pending on Android (`SharingInProgressException`).

### Pitfall 11: Android cleanup race
Do not delete the shared file when `shareAsync` resolves: on Android the target app (Drive, mail) may still be reading the content URI. Clean `cache/exports/` at the start of the next export (files older than 1 hour) and optionally on logout.

```typescript
const latToY = (lat: number, zoom: number) => {
  const s = Math.sin((lat * Math.PI) / 180)
  return (0.5 - Math.log((1 + s) / (1 - s)) / (4 * Math.PI)) * WORLD * 2 ** zoom
}
export function projectToFrame(
  point: { lng: number; lat: number },
  frame: { centerLng: number; centerLat: number; zoom: number; width: number; height: number },
): { x: number; y: number } {
  return {
    x: lngToX(point.lng, frame.zoom) - lngToX(frame.centerLng, frame.zoom) + frame.width / 2,
    y: latToY(point.lat, frame.zoom) - latToY(frame.centerLat, frame.zoom) + frame.height / 2,
  }
}
export const metresPerPixel = (lat: number, zoom: number) =>
  (40075016.686 * Math.cos((lat * Math.PI) / 180)) / (WORLD * 2 ** zoom)
```

## Open Questions

1. **Photos "grouped by factor"**
   - What we know: attachments carry no factor link; metadata is `source`, `file_name`, size fields.
   - What is unclear: whether the owner expects factor tagging in the capture flow.
   - Recommendation: print photos ungrouped in `updated_at` order (D-05 is conditional: "when linked"); note factor tagging as a future seed (needs form, queue payload and API). No question blocks planning.
2. **Sheet fidelity beyond counts**
   - What we know: strata tiers, aquatic/rocky types, DMH groups and H evidence are never stored, so the PDF can only show counts.
   - What is unclear: whether the owner accepts "same info" at count level.
   - Recommendation: state it in the summary of the plan and in the owner phone check; do not add data capture in this phase.
3. **Observer and header fields without data**
   - Recommendation: observer from the profile; omit owner, contact, altitude, comments; derive INSEE commune/département code from the cadastral id only if the owner wants it (cheap, pure).
4. **Scale lines from the catalogue hints**
   - Recommendation: include `factorInputHints[factor][2]` per factor (existing strings). If the owner finds the page too dense, drop it behind one constant.
5. **Where the history cache is written**
   - Recommendation: in `useParcelSurveyHistory` success branch (and nowhere else), keyed by parcel id, with `fetched_at`; the export prints the date and omits the section with the catalogue note when nothing is cached or the survey is the parcel's first.
6. **Android layout scale**
   - Recommendation: Wave 0 spike measures it once; hard-code the measured constant with a comment and a test of the profile function.
7. **Cap value**
   - Recommendation: start at 24 photos and 800 px; the spike's measurements decide the final numbers (planner's discretion per CONTEXT).

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|

| V3 Session Management | no | unchanged |

### Known Threat Patterns for the stack
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| HTML/script injection through a site name, observer name or genus text into the print WebView | Tampering / Elevation | `escapeHtml` on every interpolation; CSP meta `default-src 'none'; img-src data:; font-src data:; style-src 'unsafe-inline'`; no `<script>` ever emitted; test with `<script>` and `"onerror=` payloads |
| Path traversal or odd characters in the exported file name | Tampering | ASCII slug, length cap, fixed directory, delete-then-move |
| Leakage of another account's cached data on a shared phone | Information disclosure | `parcel_history:` keys deleted in `clearLocalIbpData`; exports under cache |
| PDF leaves the device with exact coordinates and the observer name | Information disclosure | User-initiated share only (OS share sheet); no automatic upload; owner informed in the phone check |
| Network side effects from the print WebView | Information disclosure | CSP above; images, fonts and map inlined; the only network paths (parcel fetch, remote style) are optional, bounded and skipped offline |
