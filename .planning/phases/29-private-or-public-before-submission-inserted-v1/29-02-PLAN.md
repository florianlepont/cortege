<objective>
Make the phone store the visibility choice safely before any screen exists for it: new drafts default to shared (D-04), the draft write path stops re-writing visibility from stale React state (the 29-RESEARCH M3.1 defect that would silently overwrite the finish choice), and a change on an already submitted survey is refused locally (D-07 client guard). No SQLite migration (D-14).

Purpose: `REQ-C-privacy-choice` sub-claim C2 (stored on the draft, default shared, survives an interrupted submit) and the client half of C3.
Output: storage defaults and guard, the draft write path without visibility, SQLite and hook tests.

Accepted consequence (29-RESEARCH Q2, orchestrator decision): drafts created before this phase hold 'private' locally and on the server, so the finish step opens on "Privé" for them; new drafts open on "Partagé avec l'association". No data fix.

Not implemented on purpose: the optional defence of 29-RESEARCH M3.3 (treating a server read-only refusal on a queued visibility operation as benign). The local frozen guard below prevents the case, and the finish drains the queue before it submits; a refusal would still show as the existing visible "Relevé déjà soumis" blocked state, never silently.
</objective>
