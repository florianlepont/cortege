<objective>
Freeze visibility at submit on the server, on every write channel, with the existing error policy and without breaking idempotent replays (D-07), and close the two time-of-check windows against submit (PATCH routes had no row lock and no status guard). Drafts keep changing visibility freely with their `visibility_changed` event (D-08). The sync wire shape stays as it is (D-14).

Purpose: `REQ-C-privacy-choice` sub-claim C3 (read-only after submit on every write channel), SC1.
Output: the read-only rules in the normalisation helpers, the service guard with locks, unit specs and the four e2e suites (including a deterministic race test).

D-07 refinement to record in the SUMMARY (orchestrator decision 1): CONTEXT D-07 wrote "422 submitted_read_only_fields" for every channel; this plan keeps the documented per-channel policy (api-contract-v1.md lines 593-594): 422 on `PATCH /surveys/:id`, `PATCH /surveys/:id/visibility` and sync `visibility_update`; 409 `survey_submitted_read_only` on an upsert with a higher version; 409 `sync_version_conflict` on a same-version upsert. Plan 29-10 records it in the contract.

Wave note: e2e on `ibp_test`; this plan depends on 29-04 only so that no two API e2e sessions run at the same time (no code dependency).
</objective>
