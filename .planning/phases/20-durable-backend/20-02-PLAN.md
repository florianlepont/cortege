<objective>
Give PostgreSQL a scheduled, unattended backup and a proven restore path, closing the
presentation document's own "PoC fonctionnel — déploiement sur solution pérenne à faire" flag.
Prove the backup+restore pipeline against a disposable local database — never the production VPS —
and document exactly what deploying the schedule to production requires.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: Backup script</name>
  <action>
    `infra/vps/backup-postgres.sh`: `pg_dump --format=custom` run inside the `postgres` compose
    service, written to `$BACKUP_DIR` with a UTC timestamped filename, rejected if under 1 KiB
    (pg_dump failure / empty database signal), retention pruning of dumps older than
    `$RETENTION_DAYS` (default 14). Resolves the real `POSTGRES_USER`/`POSTGRES_DB` from the
    running container's own environment rather than re-parsing the env file.
  </action>
</task>

<task type="auto">
  <name>Task 2: Restore script</name>
  <action>
    `infra/vps/restore-postgres.sh &lt;dump&gt; [target-db]`: creates a brand-new database (refuses
    if the name already exists — never overwrites the live database), restores the dump into it,
    reports table and `surveys` row counts. Validates the target database name against a safe
    identifier pattern before using it in SQL.
  </action>
</task>

<task type="auto">
  <name>Task 3: systemd units</name>
  <action>
    `cortege-backup.service` / `cortege-backup.timer`, matching the existing
    `cortege-deploy.*` pattern. Daily schedule, off the deploy-timer's 5-minute cadence.
  </action>
</task>

<task type="auto">
  <name>Task 4: Document and rehearse</name>
  <action>
    Add a "Backups" section to `infra/vps/README.md` (install, run-once check, rehearsal command,
    the documented-but-not-implemented offsite-copy gap). Retitle "Restoring the database" to
    "Restoring the database (disaster recovery)" and point it at the real restore command.
    Then actually run the backup and restore scripts against the local dev Compose stack
    (`infra/docker-compose.yml`), seeded with a real user/survey row, and record the output.
  </action>
  <verify>
    Backup produces a non-empty custom-format dump; restore into a new database reproduces the
    seeded row and the full 16-row `schema_migrations` history; restoring into an already-existing
    database name fails with a clear error; an invalid target database name is rejected before any
    SQL runs.
  </verify>
</task>

</tasks>
