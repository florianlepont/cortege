<objective>
Add one additive, nullable field, `ibp_method_version`, to the two parcel history payloads the app reads (own parcel history and another member's survey history), with the shared wire type, the mobile-local type, the API contract and tests.

Purpose: D-10 (cut the curve between v3.0 and v3.2, compare factors only within one method) cannot be drawn without the method of each history item. This is the only API touch of the phase (UI-SPEC flag 1, RESEARCH R1); CONTEXT expected no API change, so the plan records the exception explicitly.
Output: the field on both endpoints, the types, `api-contract-v1.md`, unit specs and e2e assertions.

CI note: editing `packages/**` triggers the `native-android` and `native-ios` jobs (path filter in `.github/workflows/ci.yml`) and `image-check`/`build`. This is a CI cost, not a blocker; keep the type in the package (single wire contract).

Known edge, documented and NOT changed here (RESEARCH Open Question 2): both history queries return the OLDEST rows (`ORDER BY ... ASC LIMIT`, default 20 for the parcel endpoint, `COMMUNITY_HISTORY_LIMIT = 20` for the community one). A parcel with more than 20 surveys would lose its newest ones. Not reachable with current data (prod is test data).
</objective>
