# Phase 25 - UI Design Contract

> Visual and interaction contract for the global search. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 25-CONTEXT.md (D-01..D-11, locked), sketches 013 (entry decided in words), 014 C, 015 A (locked), CLAUDE.md, charter section 13, the in-repo UI code.
> The app is React Native (Expo). No shadcn, no Tailwind: the design system is the in-repo one (`useBrandTheme()`, `brand-tokens.ts`, `mobile/src/ui/*`). "px" below means React Native points (pt).

## Scope of the contract

One page, one stack (`SearchStack`), reached from the tab bar on every platform:

| Platform | Entry |
|----------|-------|
| iOS (native tree, Release) | Existing native search tab (`role: "search"`, SF Symbol `magnifyingglass`, drawn by iOS 26 as its own round button beside the bar). Unchanged. No header magnifier anywhere (D-01). |
| Android, Expo Go, `EXPO_PUBLIC_ENABLE_NATIVE_TABS=false` in dev (JS tree) | New 4th tab in the JS bar, last position, label "Rechercher" (`fr.navigation.tabs.search`, already in the catalogue), glyph `search-outline` (already in `JS_TAB_ICONS`), same moss dot under the active glyph (`JsTabIcon`). |

Screens (all inside `SearchStack`, the tab navigator is shared by both trees):

| Route | Purpose |
|-------|---------|
| `searchHome` | The search page: field, then start page OR best result + groups OR no-result |
| `searchGroup` (new, params `{ group: "mine" \| "community" \| "places" \| "parcels"; query: string; memberName?: string }`) | The "Voir les N" list of one group (and the filtered community list of one member) |

Removed: the search button in the Mes Relevés title bar (Android and JS tree), the `surveySearch` route of `SurveysStack`, the scope segments (Mes relevés / Communauté), the "Annuler" button and the `canGoBack` branch of the old route. Mes Relevés keeps its list and its "+" button.

## Spacing Scale

Declared values, all from `brandSpacing4` (4-grid):

| Token | Value | Usage on this page |
|-------|-------|--------------------|
| xs | 4 | Gap between title and meta lines; icon to label in notices |
| sm | 8 | Gap field icon to text; gap between best-result eyebrow and title block |
| smd | 12 | Page top padding below the safe area; gap between field and first block; gap between two blocks (best result, groups) |
| md | 16 | Page horizontal padding; row horizontal padding; card padding of the best result; leading tile to text is 12 |
| lg | 24 | Gap between the last block and the tab bar clearance; start page vertical rhythm |
| xl | 32 | Start page intro top offset (below the field) |
| xxl | 48 | Start page intro icon-to-title block when no recent searches exist |
| 3xl (64) | not used | |

Fixed sizes (all multiples of 4 except hairlines):
- Search field: min height 48 (`brandComponentTokens.field.minHeight`), radius `brandRadius.card` (22), 1 pt hairline.
- Group card: radius 22, 1 pt hairline (`glass.cardBorder`), rows divided by 1 pt `colors.divider`.
- Compact row: min height 52 (`RECENT_LAYOUT.rowHeight`), vertical padding 6, leading tile 32 (radius `brandRadius.badgeSm` = 12), score ring 32 (`RECENT_LAYOUT.ringSize`).
- Group header: 44 high (the "Voir les N" link is the 44 pt target, like "Tout voir" on Accueil).
- Best-result decorative strip: 48 high, inside the card clip.
- Clear (x) and "remove recent" targets: 44 x 44 (glyph 18).
- Screen bottom padding of the scroll: tab bar height (`useAppBottomTabBarHeight`) + 24.

Exceptions: 1 pt hairlines; the 1 pt chip padding used by the survey status chip (inherited from `RECENT_LAYOUT.chipPaddingY`); row vertical padding 6 (`RECENT_LAYOUT.rowPaddingY`, inherited). Touch targets are never below 44.

## Typography

Declared from existing roles (no new font file, no new role). Four sizes (20, 16, 13, 12) and two weights (Regular 400 = `Jost-Regular`, SemiBold 600 = `Sora-SemiBold` / `Jost-SemiBold`).

| Role | Size | Weight | Line height | Token |
|------|------|--------|-------------|-------|
| Best-result title | 20 | SemiBold (Sora-SemiBold) | 25 (1.25) | `brandTypeScale.title3` + `brandTypography.screenTitle.fontFamily`, max 2 lines |
| Field text, row title | 16 | SemiBold (Sora-SemiBold) | 20 (1.25) | `brandTypography.input`, row title 1 line |
| Group header, "Voir les N", "Réessayer", "Effacer", best-result eyebrow | 13 | SemiBold (Sora-SemiBold) | 18 (1.4) | `brandTypography.sectionHeader`; links in `visual.accentText` |
| Meta, notices (offline, error, loading), no-result body, intro body | 13 | Regular (Jost-Regular) | 18 (1.4) | `brandTypeScale.footnote`, `colors.textSecondary` |
| Tab label (existing) | 12 | SemiBold (Jost-SemiBold) | 16 | `brandTypeScale.caption` through `jsTabScreenOptions`, one line, never wraps |

Notes:
- The no-result heading and the start-page intro title use the 16 SemiBold role, centred.
- Link weight: SemiBold, not the ExtraBold `label` role of Accueil's "Tout voir", to keep two weights. The visual difference is negligible; Phase 37 may harmonise both.
- Dynamic Type: all text through `AppText` (default cap 2x). Row titles stay one line and truncate at the tail; the best-result title may take two lines; meta lines one line. Rows use `minHeight`, never a fixed height, so they grow with the text. Tab label is capped by the bar itself and never wraps.

## Color

All values come from the theme; light and dark switch with the system only.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `ScreenFrame` canvas + halo (`colors.canvas`, `visual.backdrop`) | Page background, start page, no-result page |
| Secondary (30%) | `visual.glass.cardFill` / `cardBorder` / `cardShadow` | Search field, best-result card, every group card, recent-searches card |
| Accent (10%) | `visual.accentText` (forest in light, light green in dark) | Reserved list below |
| Destructive | not used on this page | Clearing recents is not destructive for user data and has no confirmation |

Accent reserved for (exhaustive):
1. The "Voir les N" link in a group header.
2. The "Réessayer" link in a group error line.
3. The "Effacer" link of the recent searches.
4. The "Voir sur la carte" affordance (glyph `map-outline` + label) at the foot of a place or parcel best-result card.
5. The active tab glyph and dot (existing `tab.activeTint` / `tab.dot`).
6. The glyph inside the 32 pt leading tiles (`visual.glass.iconTint`), over the tile fill `visual.glass.iconTile` (18% moss).

Other colour rules:
- Titles `colors.textPrimary`, meta and notice text `colors.textSecondary` (both verified at 4.5:1 or more on the glass fill and the canvas in both schemes by the existing contrast tests).
- Offline line: glyph `cloud-offline-outline`, `colors.textSecondary`. Error line: glyph `alert-circle-outline` in `onSurface.danger`, text in `colors.textSecondary` (the tone stays calm, the glyph carries the alert; no red text, no tinted box).
- Survey rows keep the colours of the shared rows: left accent bar tone, `ScoreRing` score colours, status chip tones. Nothing new.
- Placeholder text `colors.textSecondary`. Selection and caret use the platform defaults.
- No `borderWidth` on a gradient view; no `borderCurve`.

## Layout and component contract (`searchHome`)

Top to bottom, inside the route's `<ScreenFrame>` (no header, `headerShown: false`, safe-area top + 12):

```
[ field: search-outline | text | spinner (while busy) | clear (x) ]
(start page)  OR  (best result card, groups)  OR  (no result)
```

### 1. Search field
- Same glass field as today (`createSearchStyles.field`), height 48, `brandTypography.input`.
- Leading glyph `search-outline` 20, `colors.textSecondary`. Placeholder `fr.search.field.placeholder`.
- `TextInput`: `returnKeyType="search"`, `autoCorrect={false}`, `autoCapitalize="none"`, `maxLength={100}` (the API limit), `accessibilityRole="search"`, `accessibilityLabel` + `accessibilityHint` from the catalogue, `testID="search-field"`.
- Trailing, right to left: clear button (`close-circle-outline` 18, 44 x 44 target, only when text is not empty, `testID="search-clear"`), and left of it a 16 pt `ActivityIndicator` (small, `colors.textSecondary`) shown only while a network group is waiting for the debounce or loading (the debounce feedback; hidden from accessibility, the live region carries the meaning). No "Annuler" button: the page is a tab, not a modal.
- Focus: the field takes focus when the tab becomes focused AND the query is empty (keyboard up, the start page is visible above it). Returning to the tab with a non-empty query does not reopen the keyboard. Pressing the already active tab scrolls to top and focuses the field.
- Return key: dismisses the keyboard, saves the query as a recent search. The list uses `keyboardShouldPersistTaps="handled"` and `keyboardDismissMode="on-drag"`; iOS uses `automaticallyAdjustKeyboardInsets`.
- Android: the search tab sets `tabBarHideOnKeyboard: true` so the bar does not ride on top of the keyboard.

### 2. Start page (query shorter than 2 characters after trim)
Replaces everything under the field.
- With recent searches: a group header "Recherches récentes" with the link "Effacer" (44 pt target, clears all, no confirmation), then ONE glass card with up to 8 rows. Row: 32 pt tile (`time-outline`), query text (16 SemiBold, one line, tail truncation), trailing remove button (`close-outline` 18, 44 x 44, removes this entry). Pressing the row fills the field with that query, dismisses the keyboard and searches at once (no debounce). Row min height 52, press feedback = `RipplePressable` wave (Reduce Motion: highlight fade).
- Without recent searches (first use, or all cleared): centred block, `search-outline` glyph 48 in `visual.glass.iconTint` inside a 96 pt round tile (`glass.iconTile`), then the intro title (16 SemiBold, `textPrimary`) and body (13 Regular, `textSecondary`, max width 280, centred). Top offset `xl` (32) under the field.
- Entrance: sections slide in with `useFocusEntrance` / `EntranceView` when the tab becomes visible (not on each keystroke). Reduce Motion: none.

### 3. Results page (query of 2 characters or more)
Order, with `smd` (12) between blocks. Blocks that have nothing to show disappear (except offline, error and loading lines of network groups).

**3a. Best-result card** (sketch 014 C), only when at least one result exists.
- `AppCard variant="glass"` (not a `ForestCard`), padding 16, radius 22, clipped (`overflow: hidden`), the whole card is one `RipplePressable`, `testID="search-best-result"`, `accessibilityRole="button"`.
- Content: eyebrow `fr.search.best.title` (13 SemiBold, `textSecondary`), then a row: 40 pt leading tile with the type glyph, a text column (title 20 SemiBold up to 2 lines, meta 13 Regular up to 2 lines), trailing `chevron-forward-outline` 18.
- Place and parcel only: under the text, a 48 pt decorative strip with the static contour signature (`ContourLines animated={false}`, decoration only, hidden from accessibility, no live map and no map thumbnail because tiles are not available offline) and, below it, the line "Voir sur la carte" with `map-outline` 18 in `accentText`. Survey and member cards have neither strip nor map line.
- Type glyphs (leading tile and rows): own survey `leaf-outline`, community survey `people-outline`, member `person-outline`, place `location-outline`, parcel `grid-outline`.
- Selection rule (D-02), first match wins:
  1. The query is a valid parcel number and the parcel lookup returned it: the parcel.
  2. The first place, when the provider marks it confident (score at or above the threshold the plan fixes): the place.
  3. A member whose display name matches the query (case and accent insensitive, whole-word prefix): the member card.
  4. The first own survey (name match).
  5. The first community survey.
- The card promotes a result out of its group's summary: that row is not drawn twice. The group count N still includes it.
- Contents per type: survey: title = site name (or `fr.common.untitledSurvey`), meta = status line as in the rows, trailing score ring instead of the chevron; member: title = display name, meta = "N relevés terminés"; place: title = name, meta = kind + context; parcel: title "Parcelle AB 0123", meta = commune and code (and "1 relevé" when the API gives the count).

**3b. Groups**, fixed order: Mes relevés, Communauté, Lieux, Parcelles. Exception: when the query is a valid parcel number, Parcelles moves first (sketch 014 C, second phone).
- A group = `AppSectionHeader` (title 13 SemiBold + trailing link "Voir les N", 44 pt target) above ONE glass card of at most 3 slim rows (same construction as `RecentSurveysSection`: shell with glass + clip + 1 pt separators). `testID="search-group-{mine|community|places|parcels}"`, header `accessibilityRole="header"`.
- "Voir les N" appears only when the group has rows beyond those drawn (and beyond the one promoted to the best-result card). N = number of results the group holds (community cap 50, places and parcels cap 10); when the server hit its cap the label gets a plus ("Voir les 50+"). It opens `searchGroup`.
- The Communauté group lists, in this order: the matching member row (only when the query matches an author name; at most one in the summary), then community surveys.
- Row anatomy (slim, 52 high, press = green wave, `feedback.selection()` on open):

| Type | Leading | Title (16 SemiBold, 1 line) | Meta (13 Regular, 1 line) | Trailing |
|------|---------|-----------------------------|---------------------------|----------|
| Own survey | 4 pt accent bar (status tone, as `SurveyRowFrame compact`) | Site name | Status chip + short date (exactly the Accueil recent row) | `ScoreRing` 32 (completion arc for drafts) |
| Community survey | 4 pt transparent bar | Site name | "par {author} · Terminé le {date}" (existing `fr.surveyList.community.meta`) | `ScoreRing` 32 |
| Member | 32 tile `person-outline` | Author display name (a member row exists only for a non-empty name) | "N relevés terminés" | `chevron-forward-outline` 18 |
| Place | 32 tile `location-outline` | Place name | "{kind} · {context}", e.g. "Commune · Seine-et-Marne (77)" | `chevron-forward-outline` 18 |
| Parcel | 32 tile `grid-outline` | "Parcelle AB 0123" | "{commune} ({INSEE code})" + " · 1 relevé" when known | `chevron-forward-outline` 18 |

- Matched text is not highlighted in this phase (calm list, no extra weight).
- Group lines that replace the rows (inside the group card, never hiding the header):
  - Loading, first load of that group: one 52 pt row with two `Skeleton` lines (60% and 40% wide, 14 and 12 high) and a 32 pt `Skeleton` disc; `accessibilityLabel` "Recherche en cours". Later loads keep the previous rows on screen (no dimming) and only the field spinner turns.
  - Offline (network group, no connection): one 52 pt line, `cloud-offline-outline` 18 + the offline sentence (13 Regular, up to 2 lines). No button: the group re-queries by itself when the connection returns.
  - Error (request failed while online): one line, `alert-circle-outline` 18 in `onSurface.danger`, the group error sentence (13 Regular, up to 2 lines) and trailing "Réessayer" (13 SemiBold, `accentText`, 44 pt target, `testID="search-retry-{group}"`). Only that group re-runs. A failing group never touches the other groups.
- Own surveys are filtered on the phone on every keystroke (no debounce, no network); the three network groups wait for the debounce.
- Offline: Mes relevés shows its results at once; Communauté, Lieux and Parcelles each show header + offline line for any query of 2 characters or more (D-10). Online, Lieux is requested for every query, Communauté for every query, Parcelles only when the query looks like a parcel number (the group is absent otherwise).

**3c. No result**
- Shown when every group has finished, none has a row, and no network group is in loading or error state.
- Centred block under the field (offset `xl`): title "Aucun résultat pour « q »" (16 SemiBold) and body (13 Regular, `textSecondary`, max width 280). `accessibilityLiveRegion="polite"`, `testID="search-no-result"`.
- Offline variant: title "Aucun de vos relevés ne correspond à « q »", body "Les relevés de la communauté, les lieux et les parcelles demandent une connexion." The three offline group lines are still drawn below the block.
- If some network groups are in error while the others are empty, the error lines show under the no-result block; the title stays "Aucun résultat pour « q »".

### 4. Full list (`searchGroup`)
- Pushed from "Voir les N" or from the member best-result card / member row. Native stack, same chrome as the other sub-pages (`pageTitleOptions(theme)`: native collapsing large title on iOS, own title elsewhere), `ScreenFrame` (largeTitle on iOS native tree).
- Title: "{Groupe} · {N}" (e.g. "Communauté · 6"); the member variant: "Communauté · {N}" with the caption "Relevés de {nom}". Back label "Rechercher". Under the title a one-line caption "Pour « q »" (13 Regular, `textSecondary`).
- Body: `FlatList`, `gap` 12 (`smd`), horizontal padding 16, bottom clearance as above. Rows are the REGULAR density of the same row types: `SurveyRowFrame` glass cards for surveys (as in Mes Relevés today, with swipe-to-delete for own surveys), and the same glass card shape with the 32 pt tile / chevron anatomy for member, place and parcel (min height 56). `ListEntranceRow` for the first 8 rows (no replay on scroll).
- "Mes relevés" list only: keeps the chip row of the old page (Brouillons, Terminés, Avec photo, sort cycle) above the list (OA-54 filters keep a home; the summary has none). Chips reuse `fr.surveyList.search.chips`, `sort`, `sortA11y`.
- The group's states apply inside the page: loading = three skeleton rows, offline = the offline sentence centred, error = sentence + "Réessayer" button (`AppButton` secondary), empty = "Aucun résultat pour « q »".
- Back returns to `searchHome` with the query and results intact.

## Interaction Contract

| Moment | Behaviour |
|--------|-----------|
| Type | Trim; under 2 characters = start page; from 2 characters own results at once, network groups 350 ms after the last keystroke (`COMMUNITY_SEARCH_DELAY_MS` reused for all three). The field spinner shows from the keystroke until all network groups settle. A newer search always drops an older answer (per group). |
| Clear (x) or empty field | Back to the start page; in-flight answers dropped. Keyboard stays up. |
| Return key | Keyboard down, query saved as recent (trimmed, whitespace collapsed, at least 2 characters). |
| Open any result, "Voir les N", a recent | Haptic `feedback.selection()`; the query is saved as recent first (dedupe case-insensitive, newest first, 8 kept, stored on the phone in `local_meta`, cleared with the local data on sign-out / owner change). |
| Re-press the active tab | Scroll to top, focus the field. |
| Leave and return to the tab | Query and results are kept while the app lives; no automatic keyboard when the query is not empty. |
| Connection returns while the page is visible | Offline groups re-query by themselves; no button. |
| Result becomes stale after leaving the tab and editing a survey | Own group re-reads local data on focus. |

### Navigation targets (D-02, D-05, D-06)

| Result | Target |
|--------|--------|
| Own survey (row or best result) | `actions.openSurvey(id)` then `navigate("surveys", { screen: "surveyDetail", initial: false })` (current behaviour) |
| Community survey | `navigate("surveys", { screen: "communitySurvey", params: { surveyId }, initial: false })` (current behaviour) |
| Member (row, best result) | `searchGroup` with `group: "community"`, `query` = display name, `memberName` set: the community surveys of that author only. No profile page is added (D-04). |
| Place | `navigate("publicMap", { screen: "publicMapHome", params: { focus } })` with a new place focus (below) |
| Parcel | same, with a new parcel focus (below) |

Leaving to another tab is the existing behaviour of the search page; pressing the Rechercher tab again returns to the results.

Explorer focus (extends `PublicMapFocus`, each with a `nonce` so the same target re-focuses):
- Place: centre on `lat/lng`; zoom 13 for a commune or locality, 17 for a street or address (or fit the provider's bounding box when it gives one); a single static pin in `brandMapTokens.parcelSelected` (terracotta) with a white 2 pt ring; no survey highlight, no sheet. The pin stays until the next focus or until the user leaves Explorer.
- Parcel: fit the parcel bounds with 48 pt padding; outline and fill with the selected-parcel tokens (`brandMapTokens.parcelSelected` and `parcelSelectedFill`, stroke `strokeWidthSelected`); the parcel opens selected, with the sheet a tap on that parcel opens today.
- Explorer's tab-press reload must not cancel a pending focus (the focus is consumed once).

## Accessibility Contract

- Targets: every pressable at least 44 x 44 (rows 52, links and the clear / remove buttons 44, hit slop where the glyph is smaller).

Selected state is not used on this page.
- Focus order: field, best result, group 1 header, group 1 rows, group 2 ... Tab bar after the content.

- Colour is never the only carrier: error and offline lines have a glyph and a sentence; survey tone also has the status chip text.
- Reduced motion: no entrance, ripple becomes a highlight fade (`RipplePressable` / `useReducedMotion`), skeleton holds a fixed opacity, no layout animation. All timings with `ReduceMotion.System`.

## Decisions taken in this contract (reasoning)

| # | Decision | Reason |
|---|----------|--------|
| U-01 | One search page for both platforms: in-page glass field (as today), not the iOS native search bar | The iOS search tab only provides the tab button; the library draws no field. One implementation, same behaviour, same tests, matches D-01 "one page". |
| U-02 | No "Annuler"; clear (x) only | A tab is not dismissed; the old Cancel navigated back to Mes Relevés, which no longer applies. |
| U-03 | Search tab is last in the JS bar, label "Rechercher", `search-outline` | Mirrors iOS (search last), strings and glyph already in the catalogue and `JS_TAB_ICONS`. Four tabs at 360 pt wide leave about 90 pt per tab, enough for the 12 pt label. |
| U-04 | The Mes Relevés title-bar search button is removed on Android / JS tree | One entry per platform (D-01); keeps iOS and Android parity. |
| U-05 | Groups reuse the Accueil "recent surveys" pattern (one glass card, slim rows, hairlines) for all four types | Already validated by the owner on the phone; same look as the rest of the app; consistent row heights. Sketch rows were flat lists on the page background. |
| U-06 | Best-result card is an `AppCard` glass, not a `ForestCard`; the sketch's map strip becomes a static contour strip | `ForestCard` is one per screen and carries scores; a real map thumbnail needs tiles (offline impossible). The contour signature gives the same "place on a map" cue at no cost. |
| U-07 | The promoted result leaves its group's summary; N still counts it | Avoids showing the same row twice (sketch 014 C parcel phone shows the card alone). |
| U-08 | Best-result precedence (revised after research, 2026-10-09): parcel found, then member whose name matches the query, then place with score >= 0.85 and kind commune or POI, then own survey, then community survey | The geocoder score is not a confidence signal ("marie" scores 0.97 as a commune), so a matching member goes before a place. This also matches sketch 014 C, where "Marie" gives the member card. |
| U-09 | Parcelles group requested and shown only for parcel-looking queries (online); offline lines for all three network groups | Saves requests and noise online; D-10 forbids hiding network groups offline. |
| U-10 | Parcel title is "Parcelle {section} {number}" with commune and INSEE code in the meta | The sketch's "77 AB 0123" (department only) does not identify a parcel; the parser needs commune code, section and number. Accepted typed forms are for the plan (INSEE code, IDU, or commune name + section + number). |
| U-11 | Member row / card opens the community list filtered on that author (`searchGroup`) | D-04 forbids a profile page; this is the least new capability that still "finds a member". |
| U-12 | The old page's filter chips (Brouillons, Terminés, Avec photo, sort) live on the "Mes relevés" full list | The Mes Relevés list shows every survey (filtering moved to search in OA-52 / OA-54); removing the chips would lose that capability, and the summary stays uncluttered. |
| U-13 | Debounce 350 ms for the three network groups (existing constant), local filter immediate; minimum 2 characters; summary 3 rows, places and parcels cap 10, community cap 50 | Discretion areas of CONTEXT; reuses the proven constant and API maximum. |
| U-14 | Recent searches: 8 entries, saved on Return or on opening a result, stored in `local_meta`, cleared with local data | Sketch 015 A ("kept on the phone"); no new table, no migration beyond a key. |
| U-15 | Offline lines have no "Réessayer"; the group re-queries on reconnection | Sketch 015 A (C's retry-on-offline variant was not chosen); error lines do have "Réessayer" (D-02b). |
| U-16 | Typography: two weights, links in SemiBold | Template rule; the gap with Accueil's ExtraBold "Tout voir" is for Phase 37 harmonisation. |
